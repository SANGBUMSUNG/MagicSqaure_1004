## 1. 요약

4×4 마방진(1~16, 빈칸 2개, 마법합 34) 과제는 **「빈칸 위치 찾기 + 올바른 숫자 배치」**가 핵심이다. Mom Test 인터뷰([01.REPORT.md](./01.REPORT.md))에서는 학습자가 행·열만 맞춘 뒤 **대각선 검증을 빠뜨려** 직관(「뭔가 빠진 느낌」)과 **10~20초 재검산**으로 문제를 발견했다. 이 리포트는 그 불편을 **문제인식 실패조건**과 **ECB 역할 분담**으로 번역하고, PRD 초안([../docs/PRD.md](../docs/PRD.md))의 근거로 삼는다.

## 2. 과제 정의 (프로젝트 소개 기준)

### 2.1 마방진 규칙

| 항목 | 내용 |
|------|------|
| 격자 | 4×4 |
| 숫자 집합 | 1~16 (중복 없음) |
| 마법합 | 행·열·대각선(↘, ↙) 각 **34** |
| 과제 | **빈칸 2곳(0)** 의 위치를 찾고, 남은 숫자 2개를 넣어 완성 |

### 2.2 예시 격자 (연습 문제)

```
 16   3   2  13     → 합 34
  5  10  11   ?     → 빈칸 → 8
  9   6   ?  12     → 빈칸 → 7
  4  15  14   1     → 합 34
```

- 2행 4열: `34 − (5+10+11) = 8`
- 3행 3열: `34 − (9+6+12) = 7`
- 사용되지 않은 숫자: `{7, 8}` → 위 위치에 배치

### 2.3 학습 목표 (설계 연습)

- ECB(Entity–Control–Boundary) 분류 완료
- **문제인식 실패조건** 최소 3가지 도출

## 3. Mom Test → 문제 해결 연결

### 3.1 표면 문제 vs 진짜 문제

| 구분 | 내용 |
|------|------|
| **표면 (잘못된 정의)** | 「4×4 부분 마방진 풀이/검증 프로그램을 만든다」 |
| **진짜 문제** | 행·열만 맞으면 거의 끝난 것처럼 느껴지는데, **대각선 포함 완료 여부**는 「뭔가 빠진 느낌」에 의존하고, 그때마다 **직접 재검산·값 수정** 비용이 든다 |

### 3.2 증거 (인터뷰 인용)

1. 「행과 열만 맞았는데, 뭔가 빠진 느낌이더라고.」
2. 「중간에 이상해서 다시 확인해보았을 때 알았어.」
3. 「10초에서 20초 사이였던 거 같아. 검산하는데 이 시간을 사용했어.」

### 3.3 맥락 제약

- **첫 시도** — 재현 빈도는 아직 낮음; 반복 경험 수집 필요
- **동기** — 심심풀이; 강한 구매·도구 니즈는 확인되지 않음
- **비용 규모** — 검산 10~20초; 치명적이기보다 **판정 불확실성**이 핵심

## 4. 문제인식 실패조건 (3+)

Mom Test와 과제 규칙에서 도출한 **「완료로 오인하는 조건」** — 시스템·학습자 공통으로 명시해야 한다.

| # | 실패조건 | Mom Test / 과제 근거 | ECB 대응 |
|---|----------|----------------------|----------|
| **F1** | **행·열만 34**이면 완료로 판단 | 「행과 열만 맞았는데… 빠진 느낌」 | `SquareValidator` — 대각선 2개 포함 10개 선분 검증 |
| **F2** | **일부 선분만** 확인하고 나머지는 생략 | 「대각선이 빠졌나 확인해봤지」 — 사후에야 대각선 점검 | `SquareValidator` — 전체 선분 목록 순회, 누락 선분 리포트 |
| **F3** | **빈칸(0)이 남아 있는데** 숫자만 맞춘 줄 알고 종료 | 과제 정의: 빈칸 2곳 위치·값 모두 필요 | `MissingFinder` + `Cell` 상태 — `empty`/`filled` 판정 |
| **F4** | **1~16 중복·누락** 없이 합만 맞추면 OK | 마방진 정의: 1~16 각 1회 | `SquareValidator` — 사용 숫자 집합·중복 검사 |
| **F5** | **잘못된 값**을 넣은 뒤 재검산 없이 통과 | 「잘못된 값 인지하고 빈칸을 지우고 변경」 | `Solver` + `ResultDisplay` — 수정 후 재검증 루프 |

> **우선순위:** F1·F2·F3을 v0 필수. F4·F5는 PRD v0 범위에 포함.

## 5. ECB 분류 (문제 해결 구조)

```
┌─────────────────────────────────────────────────────────┐
│  <<Boundary>>                                           │
│  GridUI · InputHandler · ResultDisplay                  │
└──────────────────────────┬──────────────────────────────┘
                           │ 입력/출력
┌──────────────────────────▼──────────────────────────────┐
│  <<Control>>                                            │
│  MissingFinder → Solver → SquareValidator               │
└──────────────────────────┬──────────────────────────────┘
                           │ 읽기/쓰기
┌──────────────────────────▼──────────────────────────────┐
│  <<Entity>>                                             │
│  MagicSquare · Cell · SolveResult                         │
└─────────────────────────────────────────────────────────┘
```

| 계층 | 클래스 | 책임 |
|------|--------|------|
| **Entity** | `MagicSquare` | 4×4 격자 데이터, 마법합(34), 사용 가능 숫자 집합 |
| **Entity** | `Cell` | 값, (row,col), 상태(`empty`/`filled`) |
| **Entity** | `SolveResult` | 빈칸 좌표, 채운 값, 검증 결과, 실패조건 코드 |
| **Control** | `MissingFinder` | 0(빈칸) 위치 탐색 |
| **Control** | `Solver` | 남은 숫자로 빈칸 값 계산·배치 |
| **Control** | `SquareValidator` | 행·열·대각선 10선분 + 숫자 집합 검증, F1~F5 판정 |
| **Boundary** | `GridUI` | 4×4 격자 시각화 |
| **Boundary** | `InputHandler` | 초기 격자·사용자 수정 입력 |
| **Boundary** | `ResultDisplay` | 완료/미완료, 어떤 선분·조건이 실패했는지 표시 |

### Mom Test → Control/Boundary 매핑

| 사용자 불편 | 시스템 역할 |
|-------------|-------------|
| 「뭔가 빠진 느낌」에 의존 | `SquareValidator`가 **10개 선분 전부** 명시적 OK/NG |
| 재검산 10~20초 | `ResultDisplay`가 **실패 선분·실패조건 코드** 즉시 표시 → 수동 합산 감소 |
| 값 지우고 다시 넣음 | `InputHandler` + 재검증 루프 — 수정 후 자동 재판정 |

## 6. 해결 전략 (v0 방향)

1. **판정 우선** — 풀이 알고리즘보다 「완료인가?」를 F1~F3 기준으로 **명확히 거짓/참** 반환
2. **대각선 필수** — 검증 대상: 4행 + 4열 + 대각선 2 = **10선분** (Mom Test F1·F2 직접 대응)
3. **빈칸 상태 명시** — `Cell.state`로 0과 채워진 칸 구분 (F3)
4. **학습자 페르소나** — 손풀이·코드풀이 모두; UI는 최소, CLI/테스트 우선 가능

### v0에서 하지 않을 것

- 자동 힌트·난이도 조절 (Mom Test 미확인 니즈)
- 3×3·5×5 일반화
- 게임화·소셜 공유
