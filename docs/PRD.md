## 1. 개요

### 1.1 한 줄 정의

4×4 격자에서 **빈칸 2곳(0)** 을 찾아 1~16 중 남은 숫자를 넣고, **행·열·대각선 합이 모두 34**인지 판정·완성하는 학습용 마방진 도구.

### 1.2 배경

- **과제:** 소프트웨어 설계 연습 — ECB 분류 및 문제인식 실패조건 도출
- **Mom Test:** 학습자는 행·열만 맞춘 뒤 대각선을 빠뜨리기 쉽고, 「뭔가 빠진 느낌」과 10~20초 재검산으로 문제를 발견함
- **목표:** 직관에 의존하지 않고 **명시적 검증·판정**으로 완료 여부를 알려 준다

### 1.3 계약 모델 (INV · E · AC)

[AGENTS.md](../AGENTS.md) Dual-Track TDD 규칙에 따라, 모든 테스트·구현은 아래 계약 ID를 참조한다.

| 계층 | ID 접두사 | 정의 | 검증 위치 |
|------|-----------|------|-----------|
| **Invariant** | `INV-*` | 어떤 입력에서도 깨지면 안 되는 **도메인 불변식** | `tests/entity/` |
| **Entity** | `E-*` | Entity 데이터·상태 **구조 계약** | `tests/entity/` |
| **Acceptance** | `AC-*` | 사용자(학습자)가 **받아들이는 완료·판정 조건** (Mom Test 근거) | `tests/boundary/` · 통합 |

> Mom Test는 기능 나열이 아니라 **테스트 가능한 AC·INV 발견** 도구였다.  
> 문제인식 실패조건(F1~F5)은 AC 위반·INV 미충족으로 번역한다.

## 2. 문제 정의

### 2.1 마방진 규칙

| 규칙 | 설명 | 관련 계약 |
|------|------|-----------|
| 격자 | 4×4 | INV-1 |
| 숫자 | 1~16, 각 1회 | INV-3 |
| 마법합 | 모든 행(4) + 열(4) + 대각선(2) = **34** | INV-2, INV-4 |
| 입력 | 14칸 채워짐 + **2칸 0(빈칸)** | INV-5, INV-6 |
| 출력 | 빈칸 좌표, 채울 값, 전체 검증 결과 | E-3, AC-1~AC-6 |

### 2.2 예시 (v0 기본 테스트 데이터)

```
 16   3   2  13
  5  10  11   0   → 8
  9   6   0  12   → 7
  4  15  14   1
```

정답: (1,3)=8, (2,2)=7 — `AC-1` 기준 데이터

### 2.3 진짜 문제 (Mom Test)

> 행·열만 맞으면 거의 끝난 것처럼 느껴지는데, 대각선을 빼먹었는지는 「뭔가 빠진 느낌」에 의존하고, 그때마다 직접 재검산·값 수정 비용이 든다.

→ **AC-2, AC-3**으로 명시적 판정 대체

### 2.4 표면 문제 (범위 밖 — v0에서 직접 해결하지 않음)

「풀이/검증 프로그램을 만든다」는 기능 나열. v0는 **판정 명확성(AC)** 과 **불변식(INV)** 충족에 집중.

## 4. 불변식 (INV)

도메인에서 **절대 깨지면 안 되는 규칙**. Entity·Control 모두 준수해야 한다.

| ID | 불변식 | 검증 방법 |
|----|--------|-----------|
| **INV-1** | 격자는 항상 4×4 (16칸) | `MagicSquare` 생성 시 크기 고정 |
| **INV-2** | 마법합 `MAGIC_SUM = 34` | 상수·합산 기준값 |
| **INV-3** | 완성 격자에서 1~16은 **각 정확히 1회** (중복·누락 없음) | 숫자 집합 `{1..16}` 대조 |
| **INV-4** | 완성 격자에서 행 4 + 열 4 + 대각선 2 = **10선분** 합이 모두 34 | `SquareValidator` 전수 검사 |
| **INV-5** | 빈칸은 값 `0`으로 표현, `Cell.state = empty` | `MissingFinder` 입력 전제 |
| **INV-6** | 퍼즐 입력 시 빈칸은 **정확히 2개** | `MissingFinder` 개수 검사 |
| **INV-7** | 좌표는 `row, col ∈ {0,1,2,3}` (0-based) | `Cell` 범위 검사 |

### Mom Test · 실패조건 매핑

| 실패조건 | 위반 내용 | 대응 INV |
|----------|-----------|----------|
| F1 | 행·열만 34 → 완료 오인 | INV-4 (대각선 포함 10선분) |
| F2 | 일부 선분만 검증 | INV-4 (전수 검사) |
| F3 | 빈칸(0) 잔존 | INV-5, INV-6 |
| F4 | 1~16 중복/누락 | INV-3 |
| F5 | 값 수정 후 재검증 없음 | AC-6 (수용 기준) |

## 5. Entity 계약 (E)

Entity **데이터 구조·상태** 계약. Boundary를 import 하지 않는 순수 계층.

| ID | 계약 | 속성·행위 | 관련 INV |
|----|------|-----------|----------|
| **E-1** | `MagicSquare` | 4×4 `Cell` 배열; `MAGIC_SUM=34`; `size=4` | INV-1, INV-2 |
| **E-2** | `Cell` | `value: int`, `row: int`, `col: int`, `state: "empty" \| "filled"` | INV-5, INV-7 |
| **E-3** | `SolveResult` | `blank_positions[]`, `filled_values[]`, `is_complete: bool`, `failure_codes[]`, `failed_lines[]` | INV-3, INV-4 |
| **E-4** | `MagicSquare.from_grid(grid: list[list[int]])` | 4×4 리터럴 → `MagicSquare`; 크기·좌표 유효성 보장 | INV-1, INV-7 |
| **E-5** | `Cell.is_empty()` | `value == 0` ⇔ `state == "empty"` | INV-5 |
| **E-6** | `SolveResult.is_success()` | `is_complete` 이고 `failure_codes` 비어 있음 | INV-3, INV-4 |

## 6. 수용 기준 (AC)

**학습자가 받아들이는** 완료·판정 조건. Mom Test 증거에서 도출.

| ID | 수용 기준 | Mom Test / 시나리오 근거 | 관련 INV |
|----|-----------|--------------------------|----------|
| **AC-1** | 예시 격자 입력 시 빈칸 `(1,3)=8`, `(2,2)=7` 도출 후 **완료** 판정 | 예시 문제 · US-1 | INV-4, INV-6 |
| **AC-2** | 행·열만 34이고 대각선 불일치 → **미완료** + 대각선 실패 표시 | 「행과 열만 맞았는데…」·F1 · US-2 | INV-4 |
| **AC-3** | 10선분 중 1개라도 ≠34 → **실패 선분 목록** 반환 (수동 재검산 대체) | 「10~20초 검산」·F2 | INV-4 |
| **AC-4** | 0(빈칸) 잔존 → **미완료** + 빈칸 좌표 반환 | 과제 정의 · F3 | INV-5, INV-6 |
| **AC-5** | 1~16 중복/누락 → **미완료** + 집합 오류 반환 | 마방진 정의 · F4 | INV-3 |
| **AC-6** | 값 수정 후 재검증 시 **갱신된** 완료/미완료·실패 목록 표시 | 「빈칸 지우고 변경」·F5 · US-3 | INV-3, INV-4 |

## 8. Control · Boundary 요구사항

계약 ID 추적을 위해 Control(`C-*`), Boundary(`B-*`)는 AC·INV를 **구현·표시**하는 계층이다.

### 8.1 Control

| ID | 요구사항 | 충족 계약 |
|----|----------|-----------|
| C-1 | `MissingFinder`: 값 0인 칸 좌표 반환 (정확히 2개) | INV-6, AC-4 |
| C-2 | `Solver`: 행/열 합 34 역산 + 미사용 숫자 대조 | AC-1, INV-3 |
| C-3 | `SquareValidator`: 10선분 + 숫자 집합 검사, F1~F4 판정 | INV-3, INV-4, AC-2~AC-5 |

### 8.2 Boundary

| ID | 요구사항 | 충족 계약 |
|----|----------|-----------|
| B-1 | `GridUI`: 4×4 격자 텍스트/간단 UI | E-1, E-2 |
| B-2 | `InputHandler`: 초기 격자 수신 (CLI·리터럴) | E-4 |
| B-3 | `ResultDisplay`: 완료/미완료, `failure_codes`, `failed_lines` 출력 | AC-2, AC-3, AC-6 |

### 8.3 비기능 (v0)

| ID | 요구사항 |
|----|----------|
| NF-1 | Python 3.x, `pytest`로 INV·E·AC 계약 검증 |
| NF-2 | ECB 모듈 분리 (`entity/`, `control/`, `boundary/`) |
| NF-3 | 구현·테스트에 계약 ID 주석 (`# INV-4`, `# AC-2`) |

## 9. 사용자 시나리오

### US-1: 예시 문제 풀기 → AC-1

1. 학습자가 예시 4×4 격자(빈칸 2) 입력 (`B-2`)
2. `MissingFinder`가 빈칸 2곳 표시 (`C-1`)
3. `Solver`가 8, 7 제안 (`C-2`)
4. `SquareValidator`가 INV-4 충족 → **AC-1** 완료

### US-2: 대각선 누락 오판 (Mom Test 재현) → AC-2, AC-3

1. 행·열만 34인 격자 제출
2. `SquareValidator` → INV-4 위반, **AC-2** 미완료
3. `ResultDisplay`가 대각선 `failed_lines` 표시 — 「뭔가 빠진 느낌」 대체

### US-3: 값 수정 후 재검증 → AC-6

1. 잘못된 값 → **AC-5** 또는 **AC-3** 실패
2. 학습자 수정 (`B-2`)
3. 재검증 → **AC-6** 갱신된 판정
